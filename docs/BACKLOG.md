- [x] S1.5 Meteoalarm CAP warnings (EU), 37 member feeds every 10 min (ADR 21). Live 2026-11-19: 4,225 records, 2,422 green (level 1, dropped by design), 1,838 stored; first load 1 min 28 s, warm poll 1 min 21 s, publish latency ≤ 2.5 s. Bursts (Germany's first load was 283 changes, over a stream client's 256-change queue) are replayed in place from the change log, no reconnect (S2.6). Each country's feed is treated as a full snapshot: an active warning it no longer lists is resolved (kept in history, owner 2026-11-19), as a safety net under References, and a replaced warning it still lists is not stored again. An empty feed removes nothing, since an outage can look like one. Warnings past `attrs.expiresAt` are resolved every poll (S1.11's shared sweep), so a failing feed no longer keeps them. Later: MQTT push (`warnings-<CC>` topics) replaces polling (ADR 16); the MeteoGate API route is dropped (its token never authenticated).

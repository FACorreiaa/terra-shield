- [x] S1.5 Meteoalarm CAP warnings (EU), 37 member feeds every 10 min (ADR 21). Areas come from MeteoAlarm's own geocodes file and alias list (CC BY 4.0, no token; pinned commit + SHA-256), simplified to 0.001° on load and reloaded by `migrate` when the pin or processing changes (`seed-warning-areas` by hand). A warning's shape is its inline CAP polygons, else its EMMA_IDs, else NUTS/FIPS aliases, dissolved in PostGIS and cached by area set; a warning with an area we cannot draw is skipped, never drawn smaller, and counted in `shield_source_skipped_total{reason}`. Country: issuer plus neighbors holding ≥5% (ADR 4 amendment, owner 2026-11-19). One transaction per country; 8 min poll bound (`ingest.SlowSource`). Live 2026-11-19: 4,225 records, 2,422 green (level 1, dropped by design), 1,838 stored; first load 1 min 28 s, warm poll 1 min 21 s, publish latency ≤ 2.5 s. Bursts (Germany's first load was 283 changes, over a stream client's 256-change queue) are replayed in place from the change log, no reconnect (S2.6). Each country's feed is treated as a full snapshot: an active warning it no longer lists is resolved (kept in history, owner 2026-11-19), as a safety net under References, and a replaced warning it still lists is not stored again. An empty feed removes nothing, since an outage can look like one. Warnings past `attrs.expiresAt` are resolved every poll (S1.11's shared sweep), so a failing feed no longer keeps them. Later: MQTT push (`warnings-<CC>` topics) replaces polling (ADR 16); the MeteoGate API route is dropped (its token never authenticated).
- [x] S1.6 NASA FIRMS VIIRS NRT: public global 24 h CSVs (NOAA-20, NOAA-21, Suomi NPP; no MAP_KEY) every 15 min; HEAD + ETag skips unchanged 6–7 MB files; `COPY` → staging → insert new rows only, country assigned on insert; hourly purge > 48 h (ingest `Housekeeper`). ## Local-first development (decided 2026-11-16)

No public API host until the TestFlight build is ready to test (or the day before MVP). Until then:
- Backend runs locally: `make db-up && make migrate && make run` / `make worker`.
- The Apple app's Debug config points at `http://localhost:8080` (simulator, macOS). A physical device uses the Mac's LAN IP via a `Secrets.xcconfig` override. Debug needs an ATS exception for local HTTP; Release does not.
- The hostname is chosen at S3.9a, and Beta/Release xcconfigs get it then.

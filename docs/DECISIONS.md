# Shield — Design Decisions

## 2. Design decisions (→ `docs/adr/`)

1. **Unified event model.** One `events` table for every hazard. Hazard-specific fields (magnitude, depth, FRP, wind, PAGER) go in `attrs jsonb`.
2. **Two severities, never merged.** Store `source_severity` verbatim (GDACS green/orange/red, Meteoalarm level 2–4, USGS mag + PAGER). Derive `severity ∈ {minor, moderate, severe, extreme}` (CAP-aligned) in `internal/severity` from mapping tables per source. The tables are documented in `docs/severity.md` and covered by table tests. The UI shows both values.
   - **Physical size floors impact alerts** (owner, 2026-11-19). An earthquake already takes the highest of magnitude, PAGER and tsunami flag; GDACS cyclones now take the higher of the alert and their wind (Saffir-Simpson), and GDACS wildfires the higher of the alert and their burned area, on the one wildfire table every fire source shares. EONET prescribed burns stay on the map, always minor and flagged. The audit behind it: a 241 km/h hurricane showed as minor beside a 65 km/h storm shown as severe, and 44,000 ha GDACS fires as minor beside a 2,379-acre EONET fire shown as moderate. Tables in `docs/severity.md`.
3. **`kind` on every record:** `observed | warning | forecast | detection`. FIRMS hotspots are `detection`, never labelled "wildfire".
4. **Countries from geometry.** Natural Earth admin-0 1:50m v5.1.2 (public domain, SHA-256 pinned) goes into `countries`. `migrate` seeds it on an empty table, and `seed-countries` reloads it. `event_countries` is built with `ST_Intersects`, so an event spanning PT+ES matches both. Codes sent by sources are only hints.
   - **Warnings drawn by a national service: issuer plus neighbors from 5%** (owner, 2026-11-19, S1.5). MeteoAlarm areas follow borders finer than Natural Earth's 1:50m ones, so plain intersection tagged 702 live warnings with a neighbor; 603 of those overlaps were under 5% of the warning's area. Such a source sets a rule per event: the issuing country is always assigned, another only when it holds at least 5% of the area (which keeps real cover such as MeteoSwiss warnings for Liechtenstein). Every other source keeps plain intersection: a cyclone covering 4% of an island nation is real. Intersection is planar (geodesic took up to 32 s on one detailed area, planar ~50 ms), except for shapes wider than 180° of longitude, which cross the antimeridian and stay geodesic.
   - **Codes follow ISO 3166-1.** Somaliland → SO and Northern Cyprus → CY; Kosovo is XK/XKX. Siachen Glacier has no ISO assignment, so it is skipped. Features sharing a code (Australia and its territories) are unioned.
   - **Offshore fallback** (measured 2026-11-16). At 1:50m, coasts and estuaries are coarse: the Lisbon point is 2.3 km outside PT, the Tōhoku epicenter 81 km off JP, Gorringe Bank 211 km off PT. When nothing intersects, assign the **nearest country within 250 km** with `relation = 'nearby'` and its distance. Intersections are `relation = 'within'`. Beyond 250 km an event has no country (e.g. mid-Atlantic ridge, 892 km). The UI says "off the coast of …" for `nearby`. This needs migration 00002 (`event_countries.relation`, `distance_km`) in S1.7.
5. **Dedupe** by `(source_id, source_event_id)` upsert. Cross-source merging comes after the MVP; until then the UI shows source badges. **Amended 2026-11-16:** where two sources carry the same events from the same origin, one source owns the type instead. GDACS takes its earthquakes from USGS/NEIC, so the GDACS adapter skips EQ, and USGS (with its PAGER impact alert) owns earthquakes. Without this, every large quake would show twice. EONET, an aggregator, drops anything from GDACS, plus earthquakes and JTWC cyclone tracks, for the same reason.
6. **Revisions.** `event_revisions` records severity, geometry and status changes. This makes a later "what changed in 24h" feature cheap. A title change is recorded only together with one of those (2026-11-19): renames alone, such as Shield rebuilding MeteoAlarm titles, filled a country's recent changes and pushed the real ones out.
7. **Coverage transparency.** `source_coverage(source_id, iso2)`. The country view shows a "limited official-warning coverage" notice. Absence of data ≠ safety.
8. **Freshness.** Each event carries `observed_at`, `updated_at` and `fetched_at`. `/v1/sources` exposes each source's last success. Clients grey out stale data.
9. **Map payload.** Bbox + zoom → GeoJSON. At low zoom, cluster on the server (grid snap / `ST_ClusterDBSCAN`) and simplify polygons per zoom. Use **vector tiles (`ST_AsMVT`) only when measured payloads hurt.**
10. **FIRMS is a separate layer.** `fire_detections` keeps a 48h rolling window, purged hourly by a River job. The node has 60 GB shared, so size is watched.
11. **Licensing gate.** MVP sources: GDACS, USGS, NASA EONET, NASA FIRMS (MAP_KEY, attribution), Meteoalarm (check per-member terms). **Open-Meteo / RainViewer are excluded** (non-commercial). Sources & attribution appear in the app.
12. **Safety copy.** A permanent disclaimer says Shield does not replace national emergency services. Every event links to its official source.
13. **No Redis, Kafka, object storage or tile server in the MVP.** Add any of them only on measured need.
14. **Tests never hit real feeds.** Recorded fixtures + `httptest` stubs. DB tests use norviq's `internal/testutil/testdb.go` pattern (`TEST_DATABASE_URL`, template DB cloned per test). CI service image is `postgis/postgis:18-3.6`.
15. **Low metric cardinality.** Grafana Cloud's free tier allows about 10k series. Use per-source labels only, never per-event or per-country.
16. **Live by default: near real time wherever a source allows** (decided 2026-11-16). Shield is a "right now" product, so data age is a product feature, not an ops detail.
    - **Poll at each source's own update cadence, never slower.** Polling faster than a source publishes buys nothing, so the source sets the ceiling. Each source's published cadence and rate limits are verified and recorded in `docs/sources-licensing.md` (S0.2) before its interval is set. Starting points: USGS `2.5_day` every 60 s (the feed regenerates each minute; the day window carries revisions); GDACS and Meteoalarm every 5 min; EONET every 10 min; FIRMS every 15 min (within its MAP_KEY transaction limit; NRT detections arrive hours after the satellite pass, and the UI says so). Conditional GET keeps fast polling cheap for both sides.
    - **Prefer push over polling** wherever a source offers it (streaming feed, webhook, websocket). Re-check per source as sources evolve.
    - **Push end to end, no client polling.** Worker commit → `NOTIFY` → API `LISTEN` → SSE → client applies the change in place. The client polls only as a fallback when SSE is unavailable. On foreground, the app reconnects with `Last-Event-ID` and receives what it missed, without reloading the world.
    - **Latency budget.** Source publishes → visible on the map within **one poll interval + 5 s**. HTTP cache lifetimes stay below the shortest poll interval (`max-age` ≤ 15 s on event lists).
    - **Measure it.** `shield_source_lag_seconds` (our `fetched_at` minus the source's own update timestamp, per source) and `shield_event_publish_seconds` (commit → SSE fan-out). Alert when a source's lag exceeds 3× its interval, the same threshold as `stale` in `/v1/sources`. *Amended 2026-11-18 (S1.9):* staleness (no successful poll for 3× the interval) is the alert. Lag is bounded by the upstream's cadence, not our interval (FIRMS files change every 15–60 min on a 15 min poll), so lag alerts only when a source has plainly stopped publishing (6 h). Rules: `docs/alerts.md`.
    - **Honest freshness.** Every event shows "updated N min ago" and its source. Stale sources and events are visibly greyed (ADR 8). A source's slowness (FIRMS NRT, EONET curation) is labelled, never hidden.
    - **Limits.** Respect each source's terms and rate limits. On errors, back off with jitter and honour `Retry-After`. Being blocked by a source is the worst latency of all.
17. **Dependency injection with repositories** (decided 2026-11-16).
    - `internal/domain` holds the core types and imports nothing from the module.
    - `internal/store` has one repository per aggregate (events, sources, countries, fires). Stable queries are sqlc; bulk paths (COPY, staging tables) use pgx directly.
    - Consumers declare the narrow interface they need where they use it: `ingest.SourceStates`, `ingest.EventStore`, `ingest.FireStore`, `sources.Lister`, `server.Pinger`. No consumer imports `store`. Tests use in-memory fakes; repositories have their own tests against PostGIS.
    - `internal/app` is the only place that constructs dependencies: config, logger, pool, repositories, HTTP clients, adapters, features. `cmd/shield/main.go` only installs the signal context and calls `app.Run`.
    - Features are constructed with their dependencies and only mount routes; `server.Deps` carries just config, logger and health.
18. **API evolution: open `type`, closed everything else** (decided 2026-11-16, with the Apple client session).
    - Generated clients (swift-openapi-generator) decode string enums as closed types. One unknown value fails the whole `/v1/events` response in an app that has already shipped.
    - Event `type` will grow (landslide, avalanche, …), so the spec types it as `OpenEventType`: `anyOf [EventType, string]`. Clients map unknown values to `other`. Adding a type is not a breaking change.
    - `kind`, `status`, `severity` and country `relation` are fixed by ADRs 2–4 and stay closed enums. Adding a value to any of them is a breaking change: either `/v2`, or the server maps the new value to an existing one for older clients.
    - New optional fields and new `attrs` keys are never breaking. Clients must ignore unknown keys.
19. **Web client: React + TypeScript on Vite+, not SvelteKit** (decided by the owner 2026-11-16; merged as PR #1, `cb86131`).
    - Lives in `shield-app-web/`. Stack: TanStack Router + Query, Tailwind v4 with the generated design tokens, shadcn/ui, MapLibre GL JS 6 with a bundled Natural Earth basemap (no third-party tiles).
    - API client: `openapi-typescript` + `openapi-fetch` in `shield-app-web/packages/api-client`, generated from `backend/api/openapi.yaml`, like the Swift `shield-api` package.
    - Tooling: Vitest + Playwright; oxlint with every stable category; TS-Go type checking via `vp check`.
    - **Spec changes ship with both regenerated clients.** `ci-web.yml`'s `generated` job fails when `openapi.yaml` changes without `packages/api-client/src/schema.gen.ts` (regenerate with `bun run generate` in that package); `ci-apple.yml`'s `api` job does the same for Swift.
    - Hosting: **Cloudflare** (owner, 2026-11-19; see ADR 22).
    - Supersedes the SvelteKit plan in the original architecture.
    - **Amended 2026-11-19 (owner, via the web session): the basemap is OpenFreeMap.** The web map draws OpenFreeMap's vector tiles (public instance; commercial use allowed, no key, no request limit; terms checked 2026-11-19) through a custom dark style built from the design tokens and shipped in the app. Attribution: "OpenFreeMap © OpenMapTiles Data from OpenStreetMap". The bundled Natural Earth basemap stays as the fallback when tiles fail. This replaces "bundled Natural Earth basemap (no third-party tiles)". The map switches between globe and flat projection.
20. **Live stream: a change cursor in Postgres, NOTIFY as a doorbell** (decided 2026-11-18, S1.7 + S2.6).
    - Every insert or real change of an event takes the next `event_change_seq` value into `events.change_seq`, with `change_op` (created, updated, resolved). A deletion leaves a row in `event_tombstones` on the same sequence. Tombstones are kept: deletions are rare, and keeping them makes every cursor resumable.
    - Event writers take `pg_advisory_xact_lock` before writing, so sequence order is commit order. Without it, a reader could pass cursor 11 while a slower transaction still held 10, and miss it for good.
    - `NOTIFY shield_events` carries no payload; it only wakes readers. Each API pod's hub reads "everything after my cursor" once per wake (plus a 30 s safety poll) and fans out. A lost notification, a reconnecting listener or a new pod all recover by reading the cursor, and nothing depends on NOTIFY's 8 KB payload limit or delivery.
    - Clients resume with `Last-Event-ID` and receive the current state of each event changed since, coalesced. More than 1,000 changes means `reset` and a reload from `/v1/events`.
    - A slow client is never waited for. When its queue overflows (a burst), the hub stops filling it and its handler replays the gap from the change log in place, then carries on live (amended 2026-11-19). Only a gap over 1,000 changes, or a write that misses its deadline, closes the connection; the client reconnects and catches up by cursor, or gets `reset`. One bad connection never delays the others.
    - Rejected: an outbox table (one more table to purge, for nothing the cursor does not do); replaying `event_revisions` (it records only user-visible field changes, not creations or removals); payload-carrying NOTIFY (8 KB limit, lost when no one listens).
21. **MeteoAlarm areas from MeteoAlarm's own geocodes file** (owner, 2026-11-19; replaces the MeteoGate API route chosen 2026-11-16, whose endpoints answered 404 with the owner's token).
    - The geocodes file and alias list from MeteoAlarm's Redistribution Hub (CC BY 4.0, no token) are pinned to a GitLab commit and SHA-256, loaded into `meteoalarm_areas` and `meteoalarm_area_aliases`, and simplified to 0.001° (about 100 m) on load. `geo_datasets` records `<sha256>+<processing>`, so `migrate` reloads when either changes. A failed download warns and does not block a rollout.
    - A warning's shape comes from each CAP area's inline polygon when the sender drew one, else from its EMMA_IDs, else from its NUTS2/NUTS3/FIPS codes through the alias list. A warning with any area that cannot be drawn is skipped, never drawn smaller. `shield_source_skipped_total{source="meteoalarm"}` counts every drop by reason: `unknown_area` (a code the pinned file lacks: time to move the pin), `no_area` and `invalid`. Awareness level 1 (green, no warning in force) is dropped by design (ADR 2) and not counted.
    - Live census, 2026-11-19: 4,225 records across 37 feeds. 2,422 were level 1; of the 1,803 at levels 2–4, all could be drawn and 1,802 were stored (one had an unparsable time). Sweden and Luxembourg sent only level 1 that day.
    - MeteoAlarm releases a new dated file several times a year; moving to it is a pin bump.
22. **The web app ships first** (owner, 2026-11-19). A web page is the easiest thing to show and market before there is an App Store listing, so `shield-app-web/` launches before the Apple app reaches the store. The Apple app keeps going in parallel; nothing in M3 is cut.
    - **API go-live (S3.9a) is gated on the web launch**, not on a TestFlight build: hostname, DNS, `image.yml` with `INFRA_TOKEN`, and the `platform/infra` apps.
    - Until then the web app runs locally against a local API, configured by local environment variables. No Cloudflare token is needed yet; it is only needed if the web app ends up hosted on Cloudflare.
    - **Hosting: Cloudflare** (owner, 2026-11-19), following the house pattern in Aaru's `web-deploy.yml`: a Worker deployed with `wrangler` from CI, beta on green `main` and production on manual dispatch. CI needs `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` as GitHub secrets. The API itself stays on maat.
    - **The API hostname** is chosen by the owner once the web app is done; DNS and CORS follow from it.
    - **Amended 2026-11-19 (owner, via the web session): Saved regions and the Alert center ship on the web before the Phase 3 gate.** No API exists for them, so they are browser-local: regions live in localStorage, and alerts are derived in the browser from `/v1/stream` while a tab is open, with one stream per browser shared across tabs (Web Locks + BroadcastChannel; the API allows 8 streams per IP). Alerts cover hazards only: conflicts are monthly research data and never alert. DESIGN §10.4, §10.5 and §17 are amended in the web branch. The Apple app keeps the gate. A Phase 3 API, when built, replaces the browser-local store.
23. **AI is a first-class agent, through Anthropic** (owner, 2026-11-19). It comes after the MVP backlog is done, and the API, web and Apple app will each need work for it. Backend: an Anthropic adapter on the official Go SDK (`github.com/anthropics/anthropic-sdk-go`, https://platform.claude.com/docs/en/cli-sdks-libraries/sdks/go).
    - House rules apply (`platform/infra/docs/llm-haiku-trial.md`, read it before writing the adapter). Use the same env contract as the other apps (`ANTHROPIC_API_KEY` as a sealed secret in `horus`, `ANTHROPIC_MODEL` and the other `ANTHROPIC_*` values as literals). Send no non-default `temperature`/`top_p`/`top_k` and no assistant prefill, because Haiku 5.5 rejects them with a 400. Name types for the wire format, not the vendor. Tests use stub servers and never a real key.
24. **Apple signing shared with Khepri; Sentry and PostHog in their own projects** (owner, 2026-11-19).
    - **Signing:** Shield uses Khepri's match repo, `MATCH_PASSWORD`, `MATCH_GIT_BASIC_AUTHORIZATION` and distribution certificate (the team is at Apple's 3-certificate limit). This replaces the plan's separate Shield match repo. Shield's profiles are added once by `seed_signing`; CI runs match `readonly`. Rotating Khepri's match password or certificate now affects both apps.
    - **App Store Connect key and App Review contact:** team-level, reused from Khepri.
    - **Sentry and PostHog:** new Shield projects in the same organisations, with their own DSN and project key, so Shield's crashes and analytics stay separate from Khepri's.
25. **Tsunami warnings from NOAA's two warning centers** (owner, 2026-11-19). US products (Warning, Advisory, Watch) are official warnings for the NWS zones they name, drawn from NOAA's public forecast-zone shapefile (pinned, SHA-256, loaded by `migrate` like MeteoAlarm areas, migration 00007). PTWC's international threat messages are stored too, as `kind=forecast` guidance for national authorities at the epicenter, tagged with the countries they list, never counted as official coverage (ADR 7). Each message is a snapshot of its product. A US product holds one event per alert level, since one message can carry several coastal segments at different levels (NTWC's West Coast and Alaska product mixed Warning, Advisory and Cancellation segments in one message on 2025-07-30); an upgrade from Watch to Warning therefore ends the Watch event and starts a Warning event, rather than revising one. A level the next message no longer holds ends (cancellation, final message, information statement, downgrade), as does an expired one (US: the CAP expiry, about 3 h after each message; forecasts: 12 h after the last). US countries come from the zones named (state → US, territories → own code, British Columbia → CA), drawn or not. Wording Shield does not know is an error, retried and counted, never read as an end. Read from `previous.js`, the only list with every product (the Atom feeds keep the latest message only), every 60 s. A US warning whose zones cannot be drawn stays on the map at its epicenter, never dropped. Severity tables in `docs/severity.md`.
26. **Retention: resolved events kept 90 days** (owner, 2026-11-19). An hourly worker task deletes resolved events 90 days after they end (`coalesce(ended_at, updated_at)`), with their revisions and countries, writing a tombstone for each so stream clients drop them; batches of 200 stay under a stream client's 256-change queue. Active events are never purged. A source that still lists a resolved event past the window does not insert it again (`domain.PastRetention`), so the purge cannot churn. Stream tombstones are kept 7 days; pruning raises a stream floor (migration 00008), and a resume from a cursor below it gets `reset` and reloads. FIRMS keeps its own 48 h window. USGS quakes, which no source ever ends, resolve when they leave USGS's day window (owner, 2026-11-19), so they reach the window too.
27. **Live flights and armed conflicts as layers; no riots** (owner, 2026-11-19). Shield becomes the main project and takes over Skyvisor's live-flight idea. Flights are an ephemeral layer (positions cached briefly, never stored or tracked) from adsb.lol, the only free feed whose data licence (ODbL) allows commercial display; conflicts are UCDP events (CC BY), monthly and labelled as research estimates. GDELT is rejected for conflicts (machine-coded news, wrong geocodes) and ACLED until a paid licence is worth it. A riots/protests layer is out: point-level unrest data are either paid (ACLED) or unreliable (GDELT), and live unrest points risk steering people toward danger (App Store 1.4.5). Details and open checks in BACKLOG ("Live flights and armed conflicts"). **Amended 2026-11-19 (owner): conflicts first; menus.** Conflicts are type `conflict`, and opt-in everywhere: list, clusters, stream and country counts, summaries and changes cover hazards unless `type` or `category` names conflicts, so a conflict never raises a country's hazard severity. One server-side grouping (`domain.Category`: quakes, weather, floods, fires, volcanoes, conflicts, other) drives the map's menus; each event carries its `category`, and `category=` filters, so clients keep no copy. Military aircraft are shown as the flight feed gives them.
28. **Live flights without a key, from a per-cell cache** (owner, 2026-11-19: "no key for now"). adsb.lol allows 500 requests a day per IP without a key, so `/v1/aircraft` is demo-grade until a key or plan is chosen at launch: the API (not the worker) fetches fixed 5° cells on demand, each at most once a minute with one request in flight, paced to 450 a day, kept 50 above the quota the feed reports, and stopped on a 429 until its `Retry-After`. Budget is claimed stalest cell first, so a view's cells take turns rather than race. A cell that cannot be refreshed is served stale for up to 15 minutes, then left out (`complete: false`); every answer carries `dataAt`, so a client never shows old positions as current. A bbox may span 4 cells. Sized by simulation (`TestSteadyState`): after the burst the server gets one request every 3.2 minutes, so one viewer polling each minute sees a single cell up to 3 minutes old and a 4-cell view up to 12; with 6 cells every answer had holes, and a 10-minute stale limit left 56% of 4-cell answers incomplete. A second viewer elsewhere halves that. `cmd/aircraft-replay` serves a recorded answer for any area, so client work does not spend the quota. **Owner, 2026-11-19:** aircraft whose operators opted out of display stay hidden (1 of 316 positioned military aircraft in the recording), and launch uses a **free** adsb.lol key, not a paid plan. The feeder key (7,200 requests a day) needs an ADS-B receiver feeding adsb.lol; without one, the free adhoc key (1,000 a day, request form) is the fallback. The key arrives as an env var from a sealed secret, sent as `x-api-key`; nothing is set up until the web launch (S3.9a). The feeder tier's whole-world `re-api` answers only from the feeding IP, so the cluster cannot use it directly. Aircraft whose operators opted out of display (FAA LADD, privacy ICAO addresses) are dropped. Its ODbL attribution travels in each answer. adsb.lol is also listed in `/v1/sources` (amended 2026-11-19, for the Sources screen): the API registers it at start as `onDemand` (never stale: an unwatched layer is not a failing one) and non-hazard (never a country's coverage), and records each fetch's success or error there. The worker never polls it, so the staleness alert has no series for it. `AIRCRAFT_FEED_URL` points local client work at a replay instead of the quota.
29. **Military bases from Wikidata, as a static layer** (owner, 2026-11-19: source "Wikidata"). `/v1/bases?bbox=` serves installations from the Wikidata Query Service: CC0, so nothing is owed and no share-alike applies (OpenStreetMap's ODbL would). Shield still credits "Wikidata" and links every base to its item. The worker polls weekly, one SPARQL query per class, in priority order (missile base, submarine base, naval air base, naval base, naval shore establishment, military radar station, RAF station, Fliegerhorst, air base, Canadian Forces base, PLA military base, forward operating base, garrison, outpost, military camp, military base). An item in several classes keeps the first. A base must have an English name and coordinates on Earth. It is left out when Wikidata records a closure: an end, closure or dissolution date (P576, P3999, P582, P730), an end date on its class statement, a closed state of use (P5817), or a description that *starts* with former, closed, abandoned and the like, or places it in a world war, a museum, internment or a prison camp. Only the start counts for "former": "air base in Japan, former Japanese WW2 airfield" is Kadena, in service. Wikidata records closures unevenly, so the wording is "listed on Wikidata with no recorded closure", never "active", and every answer carries that `note`. Countries come from Shield's own geometry (ADR 4), with Wikidata's country as the fallback for islands and coasts our shapes miss. A poll replaces the whole set in one transaction or changes nothing: any class failing fails the poll (River retries), and a result more than 20% smaller than what is stored is refused as a partial answer. Recall check (2026-11-19): Ramstein, Lajes, Incirlik, Kadena, Diego Garcia, Norfolk, Camp Lemonnier, Rota, Al Udeid and Lakenheath are all present; the poll takes about two minutes of queries a week. **Barracks are left out by default** (owner call open): 1,193 more items, many of them historic buildings. The source is non-hazard (never in a country's coverage) and has no source timestamp, so only the three-interval staleness alert applies (21 days).
